# 复现边界与缺失输入

## 当前公开文件可以完成什么

- 复核 HRA005567 的 run、FASTQ 文件名、文件大小和官方 URL。
- 选择性下载原始 FASTQ，并计算本地 SHA-256。
- 从每个 `_sta.xml` 获取 read 数、碱基数、长度、GC 和质量统计。
- 使用作者代码了解 SAW 5.4.0、PASTE、SCC、Hotspot/regulon 和三维绘图的大致流程。
- 使用 Cell 补充表复核 cluster 名称、marker、图中数量、TF 模块和同源基因。
- 对将来取得的 GEM/GEF/H5AD/坐标文件进行结构检查和基础可视化。

## 当前不能完整完成什么

不能只用当前公开 FASTQ 从头得到论文最终的 62 张切片表达矩阵、38,562 个 bin50、完整细胞类型注释和最终 x/y/z 坐标，也不能完全复现在线三维系统。

## 关键输入核查

| 输入 | 是否能从当前公开资料确认 | 说明 |
|---|---|---|
| 参考基因组 | 部分具备 | 作者脚本指向 Ensembl release 93 的 GRCh38 primary assembly |
| GTF | 部分具备 | 作者脚本指向 `Homo_sapiens.GRCh38.93.gtf.gz` |
| SAW 版本 | 具备 | 作者脚本使用 SAW 5.4.0 |
| SAW 运行示例参数 | 部分具备 | 代码含 pipeline 示例，但不是完整、逐样本锁定的运行记录 |

| 芯片编号与 run 对应 | 缺失 | HRA 有 128 个 run 和 12 个实验分组，未给出完整切片映射 |
| 图像记录/IPR/原始组织图像 | 缺失 | 脚本有输入位置，但公开目录未发现实际文件 |
| 62 张切片顺序和最终 slice_id | 缺失 | 论文描述切片数，公开原始元数据不足以重建完整顺序 |
| 处理后表达矩阵 | 缺失 | HRA 目录和 Zenodo/GitHub 快照均未发现 GEM/GEF/H5AD |

| 完整细胞类型注释表 | 部分具备 | 补充表有 cluster 名称和 marker，但没有逐 bin50 注释表 |
| QC 阈值与全部中间产物 | 部分缺失 | 论文方法和代码可提供部分参数，不能锁定所有逐样本输入/输出 |

## 代码复现风险

- Zenodo DOI 实际解析到 GitHub 标签 `STO-analysis`，固定提交 `da1fa8d87d95cd9f72da37697c73436f74ea2960`。
- PASTE 示例脚本中存在未定义变量和重复切片变量，不能不经修订直接批量运行。
- 聚类脚本实现了表达邻接图与空间邻接图相加后进行 Leiden；代码注释中出现 `SSC`，与论文所称 `SCC` 存在命名不一致。
- Zenodo 元数据声明 CC BY 4.0，但 GitHub 快照中没有 `LICENSE` 文件，因此本项目不复制作者源码。

## 结论

当前公开文件适合“原始数据下载 + 方法审计 + 补充表再分析”，不构成完整的端到端重建包。若要复现最终三维胚胎，至少还需要真实芯片 mask/CID 映射、图像/IPR、run—切片映射、处理后二维表达矩阵、PASTE 变换或最终 xyz，以及逐 bin50 注释。
