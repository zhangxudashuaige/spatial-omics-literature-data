# 大文件保存方案

本项目沿用总仓库规则：GitHub 保存知识和工具，真实大文件保存在权威来源或本地硬盘。

## 三层结构

1. **权威副本**：CNGB/CNSA、恢复后的 MOSTA3D 或作者指定数据库。
2. **本地工作副本**：`data/cheng-2024-mouse-embryo-3d/`；根目录 `.gitignore` 会排除整个 `data/`。
3. **GitHub 元数据层**：本论文目录里的 manifest、来源状态、字段模板、脚本、小型样本和笔记。

## 为什么不把完整数据放 GitHub

- GitHub 普通 Git 单文件上限通常为 100 MB。
- FASTQ、SBFI、显微图像和数百万细胞表达矩阵可能达到数十 GB 或 TB。
- Git 会永久保留历史对象，即使以后删除工作树文件，仓库仍可能非常大。
- 权威数据源更新版本时，重复上传副本容易失去版本和许可信息。

## 下载前的正确顺序

1. 取得官方逐文件清单。
2. 记录文件名、格式、大小、许可和校验值。
3. 使用 `download_data.py --dry-run` 汇总所需空间。
4. 本地空间至少预留下载总量的 2-3 倍，用于解压和处理中间文件。
5. 使用 `--download --accept-large-files` 明确开始下载。
6. 下载后复核 SHA-256，并把结果保存在 manifest 或本地下载报告中。

Git LFS 只适合少量必须版本化的中等文件或真实小样本，不适合完整 FASTQ/SBFI 主数据。Zenodo/OSF 只有在许可允许二次分发时才考虑。
